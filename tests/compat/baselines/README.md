# Wrapper catalog baselines (Task 19, FR-HM9/FR-HM10)

These JSON files record the Codex and OpenCode skill-catalog footprint of
the `portable-skills/` wrapper tree **before** the Task 19 description diet
(commit `fafd1aa`, the tree as generated by
`scripts/generate-codex-skills.mjs` prior to the `COMMAND_DESCRIPTIONS` /
`AGENT_DESCRIPTIONS` tables). Task 22's activation-budget assertions
(`OpenCode <= 60% of the Task 19 baseline`) read the OpenCode number here;
the Codex numbers are point-in-time evidence for FR-HM9's "no blanked
descriptions" claim.

## `codex-catalog-pre-task19.json`

Captured with `tests/compat/scripts/capture-codex-catalog.mjs`, which
reuses `tests/compat/lib/codex-app-server.mjs` (`listCodexSkills`, the same
app-server `skills/list` JSON-RPC helper the Task 6 `OQ-2` spike and the
`codex-offline.mjs`/`codex-activation.mjs` compat scenarios use) and the
same install path as those scenarios: a throwaway local marketplace +
`codex plugin add`, then `skills/list`, then `codex plugin remove`.

Run inside the pinned Codex compat container (`versions.lock.json` pins
Codex to `0.154.0`; the image tag matches `run-suite.mjs`'s naming,
`synthex-compat-codex:stable-0.154.0`), built from
`tests/compat/harnesses/codex/Dockerfile` if it does not already exist
locally:

```bash
docker build --file tests/compat/harnesses/codex/Dockerfile \
  --tag synthex-compat-codex:stable-0.154.0 \
  --build-arg NODE_IMAGE="node:$(node -pe "require('./tests/compat/versions.lock.json').container.node")" \
  --build-arg HARNESS_VERSION=0.154.0 \
  tests/compat

PLUGIN_ROOT="$(pwd)/plugins/synthex"
docker run --rm --network none --read-only --cap-drop ALL --security-opt no-new-privileges \
  --pids-limit 256 --memory 1g --cpus 2 \
  --tmpfs /home/synthex-test:rw,noexec,nosuid,nodev,size=256m,uid=10001,gid=10001 \
  --tmpfs /workspace:rw,exec,nosuid,nodev,size=256m,uid=10001,gid=10001 \
  --tmpfs /tmp:rw,exec,nosuid,nodev,size=256m,uid=10001,gid=10001 \
  --mount type=bind,src="$PLUGIN_ROOT",dst=/fixture/synthex,readonly \
  --env SYNTHEX_COMPAT_CONTAINER=1 --env HOME=/home/synthex-test \
  --env XDG_CONFIG_HOME=/home/synthex-test/.config \
  --env XDG_CACHE_HOME=/home/synthex-test/.cache \
  --env XDG_DATA_HOME=/home/synthex-test/.local/share \
  --workdir /workspace --entrypoint node synthex-compat-codex:stable-0.154.0 \
  /opt/synthex-compat/scripts/capture-codex-catalog.mjs
```

Each entry under `skills[]` compares the app-server's reported
`description` against the `description:` frontmatter value in the
generated `SKILL.md` at capture time (`blanked` = Codex returned an empty
description for a non-empty source; `shortened` = Codex returned a
non-empty description shorter than the source). At the pre-Task-19
baseline, `totalRenderedChars` (the sum of all 46 `synthex:*` descriptions'
character counts, as actually returned by `skills/list`) is **7,476**,
`blankDescriptionCount` is **0**, and `shortenedDescriptionCount` is **0**
— Codex was not yet visibly truncating anything at 46 wrappers, but
`totalRenderedChars` was already within ~500 characters of the documented
8,000-character catalog budget (FR-HM9 rationale; see
`docs/specs/harness-modernization/spikes.md` Task 6 Unknowns), leaving no
margin as more commands gain descriptions. `synthexCount` (46) and
`sourceCommandSkillNames` (`[]`, i.e. no Codex `source-command-*` migrated
duplicate) are also asserted against by
`tests/schemas/wrapper-catalog.test.ts`.

## `opencode-catalog-pre-task19.json`

Captured with `tests/compat/scripts/capture-opencode-catalog.mjs`, which
mirrors `tests/compat/scenarios/opencode-activation.mjs` (same
`createProbeOverlay` staging, the same `opencode.json` `skills.paths`
route from the Task 21/Q7 spike, and the same
`startLoopbackOpenAIChatProvider` fake-model server from
`tests/compat/lib/loopback-openai-chat-provider.mjs`) but, instead of
asserting a per-skill activation token, it finds the first captured
request that offers the `skill` tool and measures the
`<available_skills>...</available_skills>` block inside that request's
system/developer prompt text (not a `JSON.stringify` of the whole request
body, which would inflate the byte count with escaped-newline overhead).

Run inside the pinned OpenCode compat container
(`synthex-compat-opencode:stable-1.18.15`, built the same way as the Codex
image above with `HARNESS_VERSION=1.18.15` and
`tests/compat/harnesses/opencode/Dockerfile`), with the same `docker run`
flags as `capture-codex-catalog.mjs` above except pointing `--entrypoint`
at `/opt/synthex-compat/scripts/capture-opencode-catalog.mjs`.

At the pre-Task-19 baseline, `availableSkillsBlockBytes` is **16,037**
across 46 skills (`systemPromptBytes` 27,569 total). Task 22's activation
scenario budget check divides the post-diet number by this baseline.

The script also accepts `SYNTHEX_COMPAT_CAPTURE_DEBUG=1` (opt-in, per the
Task 19 instruction to keep any scenario capture changes "optional behind
an env var") to include the full captured request bodies in its JSON
output for ad hoc debugging; this is never set when producing a
committed baseline file, and the resulting field is large and not
committed.
